# Jarvis 产品路线图（工作稿）

更新：2026-11-08。此文以当前代码、既有 MVP 设计和已完成验证为依据。用户提供的抖音视频尚无法读取画面或字幕，**本稿不声称还原了该视频的设计**；获得视频内容后应另行标注证据并修订。

## 产品目标与范围

做一个常驻 Mac、可持续升级的个人助手：用户希望它能语音交流、理解和操作电脑、控制智能家居，同时拥有科技感的启动/主界面与身份识别或登录体验。助手应在用户授权范围内执行、需要时确认，并给出可核对的结果。先在单人、本机和可取消的任务上可靠工作，再逐步连接语音与设备。

既有 MVP 的范围和审批要求以 [原始设计](2026-09-12-mac-agent-mvp-design.md) 为准。语音唤醒、远程控制、自动外发与无限后台自主操作不属于原始 MVP；它们可以成为后续阶段，但不得混同于现有交付。

## 当前基线

- 菜单栏入口及 Cmd+Shift+J：用户已验证腾出菜单栏空间后可见，并能打开 Ask Jarvis；开发版打包已合并，但尚非签名发布包。
- 本机 Qwen3 4B Instruct：中文基础问答、通过 AgentSession 的模拟工具往返已在本机验证；真实工具审批闭环未完整验收。
- 本地任务、SQLite、日志、审批和结构化记忆已有代码；需用真实任务验证失败、取消、重启与并发行为。
- 当前 shell 被有意收窄为需审批的 `pwd`，并非已具备安全运行项目测试的能力。已登录浏览器操作、文件 diff 审批后写入和真正的 GUI 点击/输入均未完成。
- 不应把当前 HTTPS 抓取等同于受控浏览器；也不应把权限提示或模型提示词当作安全隔离。

## 体验设计原则

1. **一个清晰且有辨识度的入口。** 启动与主界面可以有科幻感，但首先应看到对话、当前任务和明确的停止操作；模型、连接和权限状态可查看。登录和身份识别是明确目标，具体采用本机身份、账号或两者仍待确定，不先假设必须联网。
2. **普通对话自然，动作有依据。** 无需工具即可回答的问题直接回答；调用工具时展示目标、正在做的步骤和结果。模型的能力介绍以实际可用工具和权限为准。
3. **用户始终知道下一步。** 任务状态区分思考、等待审批、运行、完成、失败和取消。等待审批时说清具体操作、目标和风险；拒绝后不绕过。
4. **记忆可控制。** 用户可以查看、更正、删除记忆，并知道何时被使用；记忆永远不代替授权。
5. **数据流可见。** 默认使用本地模型；一旦选择云模型或访问网站，明确显示数据发送位置。日志脱敏是待验收目标：以 API key、令牌和含敏感值的工具输出为测试样本，检查界面、审计记录和错误路径。

## 分阶段计划与验收

阶段按依赖关系推进，并非所有体验都等到项目、浏览器和家居全部完成后才可见：在第一阶段稳定后即可并行制作语音与界面原型，但原型不可绕过权限和审批。

### 1. 首次可用：本地对话与可信任务

- 让应用提供可靠的模型就绪检查、服务离线提示和版本/模型标识；明确 Qwen3 4B Instruct 的下载与启动方式。
- 解决回答重复与状态误报；保证中文普通对话不强制调用工具。
- 对真实设备验证：启动 → 中文回答 → 提出受控 `pwd` → 明确审批/拒绝 → 结果/拒绝进入时间线 → 取消；检查重启后不会自动执行旧审批。
- **完成标准：** 上述真实链路在干净环境可重现；自动测试、QA、审查与 CI 通过。建立至少 20 个固定案例，覆盖中文对话、合理工具调用、拒绝和失败；记录模型版本、机器配置、每项结果、耗时及内存。通过阈值应依据首次基线确定并记录，不用单次演示代替。

### 2. 项目工作：可控读取、测试与文件修改

- 用户选择和撤销项目目录，应用明确展示权限。执行前重新检查目录、目标和授权；撤销不能使待执行任务继续使用旧授权。
- 设计并验证执行隔离：`swift test` 可运行项目提供的代码，白名单和工作目录本身不是沙箱。验证临时目录、网络、进程及越权读写风险后才开放。
- 引入真实文件的变更预览与完整 diff；审批绑定目标路径、原内容和新内容，执行前处理符号链接、外部更改和竞态。不能保证时拒绝写入。
- Git 提交、推送、删除各自单独确认。
- **完成标准：** 在用户指定的测试项目中，完成阅读、运行测试、展示 diff、批准后真实写入、结果核验及审计的闭环；拒绝时不写入，路径越界、审批后文件变化、失败不留部分写入均有测试。

### 3. 浏览器与桌面操作

- 浏览器使用独立且可管理的已登录会话；读取/填表与发送/上传/提交分开。执行层必须实际控制导航、重定向、子资源、脚本和外发；无法证明时保持禁用。
- GUI fallback 只针对允许的应用和明确目标；操作前后核验，动作可中断；截图与辅助功能权限失效时给出恢复方式。
- **完成标准：** 在测试网站上完成读取与草稿；每个外发动作都需要准确审批；目标变化、登录失效和取消均安全停止。真实点击/输入须完成设备验收。

### 4. 语音、身份和有辨识度的界面

- 将任务历史、用户可编辑记忆和项目上下文连成可追溯体验；提供清晰的来源、纠错和删除。
- 先做可选的按键说话 → 中文转写 → 答复朗读；明确麦克风状态，支持打断与关闭。验证中文识别、延迟、权限和离线行为。再单独设计唤醒词、持续监听和主动提醒，提供明确开关。
- 设计有科技感的启动动画、主界面、任务状态与语音反馈，优先保证可读、响应、可关闭及低功耗。先用可交互原型确认视觉风格，再开发正式界面。
- 设计身份与登录：先梳理本机身份、Apple 系统认证和可选账号同步的边界，分清认证、加密、设备绑定与远程访问，不以“登录”自动获得操作权限。
- **完成标准：** 用户能用语音发起、打断和取消一次已支持的任务，清楚看到转写、工具动作、审批与结果；身份状态和录音状态始终可见。选定身份方案后，验收首次设置、认证成功/失败、锁定或退出及恢复，验证登录不会自动扩大工具权限。

### 5. 智能家居与持续扩展

- 先盘点用户实际设备、品牌、现有中枢及本地/云端连接方式；适配器优先研究 Home Assistant 等已有中枢，不假定用户已经部署。
- 首个设备切片先读取状态，再选择用户明确授权的低风险灯光/场景进行控制，展示设备、动作与结果；门锁、安防、加热等高影响动作默认要求单独确认，暂不自动化。
- 建立设备授权、断连/离线、重复命令、撤销或停止、审计及误识别测试。语音识别结果不能直接绕过操作策略。
- 通过版本化工具接口和能力目录持续扩展，但新插件默认不获得系统权限；每项能力有版本、来源、权限、启停和卸载方式。
- **完成标准：** 在用户真实家庭环境中，至少一个明确授权的设备完成状态查询、命令执行、反馈及断连处理；未经授权设备不响应。

### 6. 发布准备

- 签名/公证、安装与卸载、数据备份与迁移、错误恢复、权限引导及更新机制。
- 维护文档和安全边界，使用全新用户环境执行原始 MVP 验收清单。
- **完成标准：** 给非开发者的安装与首次任务全流程可重复，已知限制明确，自动化和真机验收记录可追溯。

## 依赖与决策点

- **优先级：** 先把一次任务做对并可解释，再增加入口、设备、主动性和拟人化体验。
- **模型：** 先以本地 Qwen3 4B Instruct 为基线，记录中文、工具调用、延迟与内存；后续可提供模型选择与可选云端，不把某一模型当作安全边界。
- **平台边界：** 浏览器与操作系统级隔离是技术风险，不能以尚未接入的策略或模拟测试宣称实现。
- **语音和家居架构参考：** 将唤醒、语音识别、对话、语音合成和设备适配拆为可替换模块；Home Assistant 的 Assist pipeline 采用类似分段结构，可作为研究对象而非预设安装要求。
- **参考视频：** 待获取画面/字幕后，单独提取实际演示的交互、功能与承诺，标记已证实和待验证，再决定哪些纳入 MVP 或后续版本。

## HomeRail 参考（初步文档调研）

[HomeRail](https://github.com/xiaotianfotos/homerail) 是 MIT 许可的 TypeScript 本地工作流项目。其 README 将语音输入、生成式界面与 DAG 执行分层；它自述当前较成熟的是 DAG 运行时，而生成式界面仍在探索。Manager/Node/Worker 运行需要 Node.js、Docker 和兼容的模型端点。这里依据上游说明，尚未安装或验证其实际能力，也不能据此断言它与参考视频为同一产品。

- **语音体验：** 借鉴语音与文字并存、行动前多轮澄清；先在 Jarvis 中做可中断的按键说话和可见转写，再评估常驻唤醒。
- **任务可解释：** 借鉴任务分步、状态与证据交接；先扩展现有 SQLite 时间线和结果记录，再决定是否需要完整 DAG 或多 agent，避免为简单任务增加部署复杂度。
- **结果界面：** 借鉴按任务展示卡片、步骤和结果；生成式界面是 HomeRail 探索方向，应先用静态类型化组件和审批状态验证，不能让模型生成的界面绕过策略。
- **隔离与架构选择：** Docker worker 是可研究的隔离方案，但必须单独验证 macOS GUI、文件权限、网络和性能；目前不将 HomeRail 或 Docker 作为 Jarvis 必选依赖，也不把容器等同于安全保证。
- **适用边界：** HomeRail 侧重家庭服务器上的工作流编排；Jarvis 的短期目标是本机 Mac 操作与审批。智能家居连接仍需另行设计，不能由项目名称推断 HomeRail 已具备相应能力。
