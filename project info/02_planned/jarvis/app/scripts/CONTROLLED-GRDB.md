# Controlled GRDB build

The optional controlled build pins upstream GRDB 7.11.1 commit `b83108d10f42680d78f23fe4d4d80fc88dab3212`. `prepare-controlled-grdb.sh` archives that commit from a local git repository, verifies the complete archive and original privacy manifest hashes, applies exactly one checked manifest change, and compares every cached file and symlink before reuse. The original checkout and global configuration are not modified.

Use `scripts/with-controlled-grdb.sh <upstream-git-repository> <private-cache-directory> test` or `... build <output-directory>`. The wrapper makes a temporary application source copy and binds its manifest to the verified local dependency; the repository manifest does not accept external dependency paths. `build-dev-app.sh` copies the original privacy manifest and upstream license into the final signed app when invoked through the wrapper. The packaging script independently revalidates the source and checks the copied manifest binding. Ordinary SwiftPM commands still use the unmodified pinned remote dependency.

To update GRDB, independently review upstream changes, record the full commit, recalculate the archive and privacy manifest hashes, recheck that the manifest patch matches exactly once, inspect new uses of `Bundle.module`, update this documentation, and run clean and incremental builds, cache-tamper checks, app signature checks and relocated database migration tests. Upstream code is not committed in this repository. The cache should be private to the build user; verification is not a defense against an attacker who can change it after validation.
